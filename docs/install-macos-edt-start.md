# Плагины в EDT, установленном через 1C:EDT Start (macOS)

## Симптомы

- Плагин ставится через **Справка → Установить новое ПО**, виден в «Установленном ПО», но не загружается.
- После обновления плагина (или 1С:Напарника) продолжает работать старая версия.
- После сбоя EDT не запускается: «Не удалось получить службу приложений», журнал лежит в папке с `%20` в пути.

## Причины

1. **Установщик пишет не туда.** Профиль p2, созданный EDT Start, указывает `installFolder = <EDT>.app/Contents/MacOS` без папки конфигурации. Установщик пишет список модулей в `Contents/MacOS/configuration`, а EDT читает `Contents/Eclipse/configuration`.
2. **Устаревший кэш модулей.** EDT держит кэш загруженных модулей (`configuration/org.eclipse.osgi`). В этих установках он может не обновиться после установки: `bundles.info` уже указывает новую версию, а загружается старая из кэша.
3. **Путь с `%20`.** В некоторых запусках путь к конфигурации кодируется (`Application%20Support`), и EDT стартует с новой пустой конфигурацией.
4. **Список модулей отстаёт от установленного.** Плагины, поставленные до исправления п. 1, записаны в профиль p2, но не в `bundles.info`, который читает EDT. Пример: 1С:Напарник числился как 1.0.8, а загружался 1.0.7.

## Исправление

```bash
bash tools/edt-doctor.sh          # проверка, ничего не меняет
bash tools/edt-doctor.sh --fix    # исправление, EDT должен быть закрыт
```

Скрипт проверяет все установки EDT Start и для каждой:

| Проблема | Что делает `--fix` | Резервная копия |
|---|---|---|
| Нет папки конфигурации в профиле p2 | Добавляет `org.eclipse.equinox.p2.configurationFolder` новым состоянием профиля | `~/edt-p2-profile-backup-….tgz` |
| Список модулей отстаёт от профиля p2 | Приводит версии в `bundles.info` к установленным, добавляет недостающие модули (исходники `*.source` пропускаются), затем пересобирает кэш | `bundles.info.mnt-backup-…` рядом с файлом |
| Устаревший кэш модулей | Переносит кэш (`org.eclipse.osgi`, `org.eclipse.core.runtime`) в резервную папку; EDT соберёт новый при запуске — как `-clean`, но без правки параметров запуска | `configuration/.mnt-cache-backup-…` |
| Путь с `%20` | Создаёт ссылку с пути `%20` на настоящую конфигурацию | ошибочная папка → `~/edt-config-20-backup-…` |

Запускать после каждой установки или обновления плагинов, а также после обновления EDT через EDT Start.

**Не использовать `-clean` в `1cedt.ini`**: в установке EDT Start такой запуск привёл к старту с пустой конфигурацией по пути с `%20`.
